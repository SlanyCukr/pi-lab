# Token-efficiency pass, 2026-09-23

Tools: `analyze.py` (cost attribution from session logs), `ab.sh` + `tasks.tsv` (A/B runner),
`APPEND_SYSTEM.lean.md` (flagged prompt). Baseline window: 2026-09-16 to 09-23, all sessions.

## 1. Harness map and baseline

**Map.**
- **Request assembly:** pi 0.87.1 `agent-session.js` builds the system prompt from `_baseSystemPromptOptions`. `before_agent_start` hooks change it per run. pi-permission-system (local patch) moves the tool list to the end. pi-anthropic-auth adds the billing header and the Claude Code line.
- **Payload hooks:** `before_provider_request` hooks rewrite the payload. cache-ttl sets 1 h breakpoints in the main session. tool-groups sets `thinking.display: omitted`.
- **Tool order:** tool order is deterministic (registration order).
- **Cache:** Anthropic uses explicit breakpoints on the system blocks and the last message. The main session uses a 1 h TTL, sub-agents use 5 min. pi's idle cache warmer costs $0.26 a week, which is negligible.
- **Tool results:** bash, read and grep keep up to 50 KB or 2000 lines inline. bash saves its full output to a temp file.
- **History and compaction:** history is kept whole until compaction. `compact-at` compacts at 40 %.
- **Sub-agents:** pi-subagents runs them in-process with fresh context. Explore runs on Codex and builder on the parent model.
- **Telemetry:** pi already logs usage per request, split by billing type (input, cacheRead, cacheWrite, output) with dollar cost, in the session JSONL. No new logging was needed. `analyze.py` turns that log into the tables below.

**Baseline (one week).** Main sessions cost $453.5 and sub-agents cost $90.8.
- Main sessions: $2.98 per user message, 18.7 requests per user message.
- Cache: 96 % of prompt tokens were cache reads.
- Static prefix: about 22K tokens in `~/pi-lab`, and 18.7K in an empty project.

Sources are estimated by characters and then scaled to the real prompt tokens of each request. Tokens are priced in prefix order: cache read first, then cache write, then uncached input.

**Re-written prefix (cache misses).** These are tokens written again beyond what was new, since 09-20 12:00 on Anthropic. The biggest cost is **$80 in 42 full re-writes**:
- **bg-bash wake-ups:** 6 of 7 missed the cache. Each one also caused a second full re-write on the next normal turn. That is about $20. **Fixed** (see 3).
- **Gaps longer than 1 h:** these are TTL expiries and are expected.
- **Unexplained:** the request *after* a cold restart also missed about 7 times, about $14. A fresh-session test did not reproduce it (see 5).

**Tools (main, share of sessions that call it / error rate).**
- Frequent: bash 69 % / 4.5 %, edit 44 % / 8.2 %, write 50 %, read 38 %, todo 38 %, subagent 31 %, fetch_content 31 %.
- Rare (≤ 19 %): advisor, lens_diagnostics, web_search, lsp_navigation (6 %), steer_subagent (6 %).
- Never called in the window: `schedule_wakeup`, `loop`, and the pi-goal tools (now removed).
- Repeated errors: edit-without-read (10), permission denials of `rm -rf` (13), and edit args missing `newText` (5). Each costs one extra turn, about $0.10–0.30. The total is under $10 a week.

## 3. Changes made

- **`cache-ttl` prompt pin.** Files: `wip/cache-ttl/index.ts`, live copy `~/.pi/agent/extensions/cache-ttl/index.ts`.
  - The bug: pi 0.87.1 runs a `sendMessage(..., {triggerTurn})` wake-up through `_runAgentPrompt` without `before_agent_start`, so that request uses the un-hooked system prompt.
  - The fix: the pin reuses the system prompt of the last hooked run. It does this only when the model and tool list match. It resets on `session_start`.
  - Mock check: 4 of 4 requests had an identical system prompt. Before the fix, request 3 differed.
  - Real Opus check: two bg-bash wake-ups read the full cache (20742 and 21129 tokens), and the next user turn read 20787. One wake-up first hit a transient "Connection error." Those errors show up about 50 times a week in other contexts, and a repeat run was clean.
  - Rollback: `PI_PROMPT_PIN=0`.
- **Built-in `general-purpose` and `Plan` sub-agents disabled.** Files: `~/.pi/agent/agents/general-purpose.md` and `Plan.md`, each with `enabled: false`. Their guideline lines are gone from the `subagent` tool text too. A call to them returns `Agent type "general-purpose" is disabled`. Rollback: delete the two files.
- Earlier the same day: pi-goal removed, `web_search` allowlist.

**Flagged: lean system prompt.** File: `APPEND_SYSTEM.lean.md`. Turn it on with `pi --append-system-prompt ~/pi-lab/wip/token-audit/APPEND_SYSTEM.lean.md`; the flag replaces `APPEND_SYSTEM.md` (checked in `resource-loader.js`). Diff by instruction:

## 4. Test plan for the flagged changes

1. **Lean prompt:** run `ab.sh base 5` and `ab.sh lean 5`. That is 4 tasks × 5 reps each, about $6–10 in total.
2. **Metrics:** get cost, requests and cache share from `analyze.py --root /tmp/ab/sessions/<variant>`. Get check pass/fail and final-message lines from `/tmp/ab/results.tsv`.
3. **Ship rule:** switch `APPEND_SYSTEM.md` only if the pass rate is equal and cost per task drops. Also read the final messages side by side for the ADHD shape (first line = outcome, one next action). Record a null result too.
4. **Smoke run (n = 1, 2 tasks):** both variants passed. Cost was $0.30 base vs $0.23 lean, the static prefix 18.7K vs 15.0K tokens, and the answers had similar shape.
5. **Real usage:** use `--append-system-prompt` for a day of normal work. Then compare `analyze.py --since` numbers against the baseline week, including whether the next user message moves on or reports a problem.
6. **pi-lens lazy mode** and the **16 KB output cap:** use the same A/B with a task that greps a large repo. Add tool-error rate and requests per task as guardrails.

## 5. Gaps

- **Cold-restart double miss:** not explained. On 7 occasions the request right after a cold start read only the system prompt. A fresh `pi -p` 3-request test did not reproduce it. The next step is a wire capture of such a pair.
- **Subscription pricing:** the dollar costs use pi's list prices. Anthropic (subscription) and Codex (subscription) are not billed per token, so the "cost" is really quota pressure.
- **Thinking tokens:** the history share of thinking tokens is estimated from summarized or omitted thinking text. What Anthropic actually re-bills for thinking blocks is not visible.
- **Quality signal:** there is no automatic task-success signal from real sessions. The only guardrail today is the A/B check commands.
- **Cost per completed task:** this was approximated as cost per user message.
