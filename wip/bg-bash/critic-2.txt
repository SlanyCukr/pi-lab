**I would not ship it.** Read-only review, cross-checked against installed pi **0.85.1**.

1. **High — Foreground calls bypass project-settings trust** — [index.ts:32](/home/slanycukr/pi-lab/wip/bg-bash/index.ts:32), used at line 226. `SettingsManager.create(cwd)` defaults to `projectTrusted: true`, independently of the running session’s trust decision. An untrusted repository’s `.pi/settings.json` can supply `shellCommandPrefix` or `shellPath`; an approved foreground `pwd` then executes repository-controlled code. The command-string gate sees only `pwd`. **Fix:** use the session’s effective, trust-filtered shell configuration; do not independently reload settings with implicit trust.

2. **High — Descendants survive shutdown and timeout escalation** — [index.ts:111](/home/slanycukr/pi-lab/wip/bg-bash/index.ts:111), lines 184–198. SIGTERM can kill the shell while a worker in its group ignores SIGTERM. The shell’s exit removes `pgid` from `live`, disabling both delayed SIGKILL and the process-exit cleanup. `jobs.delete` also releases capacity although the worker survives. **Fix:** retain an owned supervisor/group leader through descendant cleanup and escalation. Merely retaining the numeric PGID introduces reuse hazards.

3. **Medium — Stale escalation timers can kill a newer job** — [index.ts:110](/home/slanycukr/pi-lab/wip/bg-bash/index.ts:110). The SIGKILL timer is neither stored nor cancelled. If job A exits after SIGTERM and its PID is reused by job B within two seconds, B puts the same number into `live`; A’s timer kills B. The set checks numeric membership, not ownership. **Fix:** store and clear escalation timers on settlement, and verify the captured job identity before signalling.

4. **Medium — Background commands lose stock session environment** — [index.ts:159](/home/slanycukr/pi-lab/wip/bg-bash/index.ts:159). Stock bash constructs environment variables including `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, and `PI_MODEL` from the execution context. Passing `process.env` instead omits them or inherits stale parent-session values. Scripts using these variables behave differently merely by enabling background execution. **Fix:** construct the same context-derived environment as stock bash.

5. **Low — Long single-line UTF-8 output is corrupted** — [index.ts:58](/home/slanycukr/pi-lab/wip/bg-bash/index.ts:58). A truncated tail starting inside a multibyte character decodes with replacement characters. If no newline exists, `indexOf()` returns `-1`, so the supposed partial-line removal removes nothing. **Fix:** align the byte slice to a UTF-8 boundary before decoding and explicitly handle newline-free tails.

The private directory/file permissions, ordinary spawn-error listener, parent FD closure, and synchronous shutdown/settlement deletion ordering look sound. Closing the parent FD after spawn is consistent with Node’s [FD-sharing semantics](https://nodejs.org/api/child_process.html#optionsstdio). I found no confirmed duplicate-delivery defect; pi’s runtime follow-up queue also guards active runs.
